# Architecture / 架構

This document describes the public frontend in this repository only. The production VESTA Scanner backend is a separate, private system and is not described here.

本文件只說明本儲存庫中的公開前端；VESTA Scanner 正式後端為獨立私有系統，不在此說明。

The page combines two data sources that are never mixed:

| Source | Real? | Where it comes from | Label on the page |
|---|---|---|---|
| Scanner events (the table) | **No — simulated** | Generated by code in the browser (and once at build time) | SIMULATED DEMO DATA |
| Market context (panel + CMC columns) | **Yes — real CoinMarketCap data, cached** | CoinMarketCap Pro API, fetched only by the server route `GET /api/cmc/context` and cached there | REAL CMC DATA · with the CMC snapshot time; STALE / PARTIAL / UNAVAILABLE when applicable |

頁面結合兩種資料來源，彼此不混用：掃描事件（表格）為**模擬資料**，標示 SIMULATED DEMO DATA；市場背景（背景區塊與 CMC 欄位）為**經伺服器快取的 CoinMarketCap 真實資料**，標示 REAL CMC DATA 並附 CMC 資料快照時間，必要時另標 STALE／PARTIAL／UNAVAILABLE。

## Components / 組成

### Next.js frontend
- Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS 4.
- One page, `/demo`, statically rendered. `/` redirects to `/demo` (`next.config.ts`). One dynamic API route, `/api/cmc/context`, never pre-rendered.
- The first render uses the default scenario at a fixed simulated time, so the server HTML and the first browser render are identical; the browser then takes over the simulated clock. The market context starts in a "loading" state and is fetched after hydration.

### UI components (`components/`)
- `demo-app.tsx` — page shell: header, language switcher, hero text, market context panel, disclaimer.
- `scanner-board.tsx` — demo banner, scenario picker, status banner, filter line, sort buttons, BTC-relationship prototype toggle, data-source legend, the ranked table and the definitions list. Visual design matches the VESTA Scanner dashboard.
- `cmc-context-panel.tsx` — market context: total crypto market cap, BTC dominance, Fear & Greed Index, the single CMC snapshot time (`as_of`), source badges and the required attribution ("Data provided by CoinMarketCap.com", linked to https://coinmarketcap.com) directly under the panel title; the same attribution sits beside the table legend whenever the CMC columns are shown.
- `cmc-cells.tsx` — four CMC columns per scanner row (CMC rank + size tier, market cap, CMC 24H spot volume, 24H / 7D change), tinted so they cannot be confused with simulated columns. Unmatched assets show "Not matched" / "No quote", never a guessed value.
- `use-cmc-context.ts` — loads the context after hydration and every 5 minutes while the page is visible.

### i18n (`lib/i18n/`)
- `messages.ts` holds every user-facing string for `zh-Hant` (default) and `en`. The `en` dictionary is type-checked against `zh-Hant`, and tests check that both have the same shape and that components contain no hard-coded Chinese text.
- `context.tsx` provides the current locale. The choice comes from `?lang=` or is remembered in the browser's `localStorage`; the page works without storage.
- Logic modules return codes (for example freshness reasons or CMC failure reasons); the UI turns codes into words.
- Event direction codes (`LONG` / `SHORT` / `NEUTRAL` in `vesta.scan.public.v2`) are shown as neutral activity words ("Upward activity", "Downward activity", "No clear direction"); the page makes no trading recommendation.

### Data adapter (`lib/data/`)
- `adapter.ts` defines `ScannerDataAdapter.getLatest()` and `SchemaValidationError`. It also reserves the *shape* of a future read-only HTTP adapter (`HttpAdapterConfig`) — interface only, not implemented.
- `mock-adapter.ts` builds the snapshot for the selected scenario at the simulated time and validates it before returning it.
- `sim-clock.ts` starts at the fictional moment **2030-01-01 09:00:00 UTC+8** when the page loads and advances in real time. Every scanner time on screen is labelled as simulated.
- `cmc-context-client.ts` — the browser's only network call besides the service worker: a same-origin `GET /api/cmc/context`. Accepts the 200 and 503 bodies and validates each with `vesta.cmc.context.v1`; anything else is rejected and never rendered.
- `cmc-view.ts` — pure view model (badges, formatting, per-symbol lookup).

### Mock scenarios (`lib/mock/scenarios.ts`)
Deterministic functions of the simulated time, based on 36 placeholder symbols:

| Scenario | Shows |
|---|---|
| `normal` | Typical board; one row with structure still pending, some data-quality flags |
| `high_vr14` | Volume ranking led by events with VR14 above 100× |
| `stale` | Snapshot 10 minutes old → "Delayed" state, dimmed table |
| `empty` | No matching events |
| `pending` | Most rows still computing trend structure |
| `low_liquidity` | Thin-market flags; 24H volume close to the 500K filter |
| `partial` | 2 of 3 market connections up → "Partial" state |
| `invalid` | Breaks the schema on purpose → rejected, error shown instead of data |

The scenario picker changes only the simulated scanner events; the CoinMarketCap context is independent of it.

### Public schema validation (`lib/schema/public-v2.ts`)
- `vesta.scan.public.v2`, written with Zod. All objects are strict (unknown keys rejected), all values bounded.
- Cross-field rules: every row meets the display filters the snapshot itself declares (VR14 ≥ `vr14_min`, known 24H volume ≥ `min_qv_24h_usdt`), 24H volume is fresh, rankings are correctly ordered and every row is ranked.
- Freshness (`lib/scanner/freshness.ts`) is recomputed from `generated_ms` against the reader's clock, so old data is never shown as fresh: older than 180 s → Delayed; scanner not running → Stopped; connections down or 24H volume unavailable → Partial.

### CoinMarketCap integration (`lib/cmc/`, server-only) — CMC API Hackathon work
- **Endpoints:** `/v1/cryptocurrency/map` (0 credits), `/v3/cryptocurrency/quotes/latest` (1 credit per 250 assets), `/v1/global-metrics/quotes/latest` (1), `/v3/fear-and-greed/latest` (1). Nothing else may be called (`endpoints.ts`, enforced by the client and the transport).
- **No visitor input:** `GET /api/cmc/context` reads nothing from the request. The symbol list is the fixed demo universe; IDs and endpoints are fixed. Only GET is exported.
- **Symbol → CMC ID** (`symbol-map.ts`): strips `USDT` and unit multipliers (`1000PEPEUSDT` = 1,000 PEPE). A ticker shared by several active CMC listings is never guessed: 13 demo tickers are pinned to IDs verified against the live map; a pin only applies if CMC still lists that ID under the same ticker.
- **Caching and credit protection** (`cache.ts`, `budget.ts`, `service.ts`), sized for the CMC Basic plan (15,000 credits/month, 50 requests/minute): one in-memory TTL cache per source — quotes 15 min, global metrics 30 min, Fear & Greed 60 min, ID map 24 h — with single-flight loading, back-off after errors (longer for rate limits) and a bounded stale window (3–6 h). At most 168 credits/day (≈ 5,040/month) **per server process**. On top of that, `CreditBudget` is a hard cap of 200 credits per UTC day per process: credits are reserved before every request, and a request that would exceed the cap is never sent (the part degrades as `RATE_LIMITED`, serving stale data while it lasts). Both limits are per process (in memory); N concurrent serverless instances can spend up to N × 200 credits/day, and CMC itself refuses requests once the plan's monthly credits are used.
- **Access and HTTP caching** (`route-handler.ts`): the route is the dashboard's own feed, not a reusable CMC data API. It answers only requests with `Sec-Fetch-Site: same-origin`, which browsers attach to every request and page scripts cannot set, so other websites cannot use it from their visitors' browsers (fetch, `<script>`, `<img>`, iframes). Anything else (another site, a sibling subdomain, a typed URL, or a non-browser client without the header) gets `403` before the CMC service runs, so it spends no credits. Every response is `private, no-store`, so no CDN copy can be served to a request that skipped the check. This is a limited browser-request restriction, not authentication and not a guaranteed anti-redistribution control: a non-browser client can send the header itself and receive what a visitor sees, just as it could scrape the page.
- **`as_of`:** when the market values were fetched from CMC — the oldest of quotes, global metrics and Fear & Greed. The ID map holds no market values and does not count. The UI shows it once, as "CMC snapshot as of … · cached, not real-time".
- **Degradation:** no key or build phase → `unavailable` (no request). One source failing → `partial` with a reason code; cached values within their window are shown with `stale: true`; older values are dropped. Nothing usable → `unavailable` (HTTP 503 with a valid body). The scanner demo never depends on CMC.
- **Contract:** `vesta.cmc.context.v1` (`lib/schema/cmc-context-v1.ts`), strict; includes `scanner_rows: "SIMULATED"` and the CoinMarketCap attribution. Validated before the route responds and again in the browser.
- **Deliberately absent:** any combination of scanner (futures) volume with CMC (aggregated spot, CEX + DEX) volume, buy / sell or long / short recommendations, scores and predictions.
- **Live smoke test:** `scripts/cmc-smoke.ts --live` (manual only; at most one request per endpoint, prints response shapes, never values of the key).

### PWA (`public/`)
- `public/demo/manifest.webmanifest` — `id`, `start_url` and `scope` are all `/demo`; standalone display.
- `public/demo-sw.js` — registered only in production builds, scope `/demo`, cache names prefixed `scanner-web-demo-`. It caches only content-hashed build assets (`/_next/static/`), the icons, the manifest and the offline page. It never caches page HTML, `/api/` paths (including `/api/cmc/context`), non-GET requests or cross-origin requests. A failed navigation shows `public/demo/offline.html`, which contains no market data.
- On activation the worker deletes only its own old caches; it never touches caches of other apps on the same origin.

### Tests (`tests/`)
Node.js built-in test runner, no extra dependencies (`tests/register.mjs` resolves the `@/` alias and compiles `.tsx` components with the project's TypeScript so they can be rendered with `react-dom/server`):

| File | Covers |
|---|---|
| `schema.test.ts` | Contract rules, using synthetic snapshots only |
| `mock-adapter.test.ts` | Determinism, simulated clock, every scenario, freshness states |
| `i18n.test.ts` | Dictionary parity, coverage of all codes, no hard-coded UI text |
| `pwa.test.ts` | Manifest, icons, isolation, service-worker caching in a sandbox |
| `corr.test.ts` | Draft contract, placeholder data, reference symbol rule |
| `security.test.ts` | The security scan passes here and catches planted problems |
| `cmc-*.test.ts` | CMC integration: symbol mapping and pins, API key handling, client errors and back-off, transport limits, cache, context contract, service fallbacks, route responses, UI rendering and labels — all with synthetic CMC-shaped data, no network |

### Security isolation / 安全隔離
- No network requests in application code, with three exceptions: the service worker (same-origin static files), the browser reader of the same-origin route (`lib/data/cmc-context-client.ts`, which may contain no absolute URL) and the server-only CoinMarketCap transport (`lib/cmc/https-transport.ts`, CMC Pro API host only, redirects refused, response size capped, no retries). Browsers never contact CoinMarketCap.
- No environment variables except `NODE_ENV`, plus, server-side only, `CMC_PRO_API_KEY` (read in `lib/cmc/env.ts`; without it the CMC context is simply unavailable) and `NEXT_PHASE` (CMC is disabled during `next build`).
- `scripts/security-scan.mjs` (also run by `npm test` and `npm run check`) fails on secret-shaped strings (including CMC-key-shaped values), connection strings, private network addresses, internal paths and hostnames, deployment-platform hosts, trading-execution endpoints, network calls outside the allowed files, the CMC API host outside `lib/cmc/endpoints.ts`, server-only `lib/cmc` imported by client code, unapproved dependencies, secret or deployment configuration files (including any file with `.env` in its name; a git-ignored, untracked, `chmod 600` `.env.local` is the only exception), and a tracked or un-ignored local rules file. Contributors' clones (with a remote and their own commit identity) pass. The maintainer-only pre-push option `--maintainer` additionally fails on non-noreply commit identities, a non-noreply repo-local `user.email`, credentials embedded in a remote URL, any remote other than the approved origin, or an origin whose fetch or push URL differs from it. With `--build` it also scans the built client bundle (and fails on source maps or on the CMC host or key name in browser code). It reports file, line and rule name, never the matched text.
- The scanner's rules are generic. Maintainers may keep extra, environment-specific deny terms in an optional local file, `security.local.json` (`{ "terms": [...], "forbiddenPaths": [...] }`). That file is git-ignored, never scanned or printed, and the scan fails if it is tracked or not ignored. A fresh checkout passes without it; `--no-local` forces generic-only mode.
- Next.js Image Optimization is disabled (`images: { unoptimized: true }`), so `/_next/image` is not served and no native image library is loaded at runtime.
- No deployment configuration is included.

## Data flow in one sentence / 一句話說明資料流

Scanner: scenario generator → schema validation → freshness check → UI words from the dictionary → table; nothing leaves the browser. Market context: CoinMarketCap → server route (fixed request, cache, validation) → same-origin JSON → validation in the browser → panel and CMC columns, always labelled with the CMC snapshot time.

掃描事件：情境產生器 → schema 驗證 → 新鮮度判斷 → 字典轉換文字 → 表格，不會離開瀏覽器。市場背景：CoinMarketCap → 伺服器路由（固定請求、快取、驗證）→ 同源 JSON → 瀏覽器再次驗證 → 背景區塊與 CMC 欄位，並一律標示 CMC 資料快照時間。
